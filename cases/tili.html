TILI — AI 판독문과 화면 수치의 불일치 해결

병리 분석 결과를 의료진과 환자에게 전달하는 서비스에서, AI 판독문과 화면 수치가 다르게 계산되는 원인을 찾아 수정한 기록

기간2026.08
팀5인 (3조)
내 역할추론 워커 · AI 연동
스택Flutter · React · Django · Celery

01서비스 소개

병리 조직 이미지를 AI가 분석해 면역세포 비율(sTIL)을 계산하고, 언어 모델인 MedGemma가 결과를 판독문 형태로 작성합니다. 의료진은 웹과 태블릿에서, 환자는 모바일에서 결과를 확인합니다. 검체와 환자가 바뀌는 사고를 막기 위해 QR로 본인을 확인합니다.

02발견한 문제

프론트엔드를 맡은 팀원이 화면 수치는 "종양 0%"인데 판독문에는 종양이 있는 것처럼 표시되는 사례를 공유했습니다.

코드를 확인한 결과, 수치 계산과 판독문용 이미지 생성 과정이 서로 다른 마스크를 사용하고 있었습니다. 판독문에 사용된 이미지를 다시 측정하니 종양 영역이 5.8% 포함되어 있었습니다.

해결: 마스크 생성 함수 통합

선택지
① 두 결과가 다를 때 한쪽 값을 보정해 맞춘다  ② 계산이 나뉘는 구조 자체를 없앤다
결정
②. 한쪽 결과값을 보정하는 방법도 있었지만, 다른 입력에서 같은 문제가 반복될 수 있었습니다. 두 결과가 consensus_mask 함수에서 생성한 동일한 마스크를 사용하도록 경로를 통합하고, 판독문 프롬프트에는 색상 범례를 추가해 AI가 참고하는 영역을 명시했습니다.
결과
같은 문제가 다시 생기지 않도록 회귀 테스트 7개를 추가했습니다.

03추가로 수정한 오류

같은 시기에 비슷한 성격의 문제를 두 개 더 찾았습니다.

증상위험바꾼 것
추론 서버가 모르는 모델 이름을 받으면, 오류 없이 더미 모델로 대신 답했다화면에는 정상 결과처럼 보인다요청한 모델과 실제로 쓰인 모델을 비교해, 다르면 즉시 중단
입력 오류(422)가 나면 "오류"라는 메시지만 남았다원인을 모른 채 재시도만 반복한다서버 응답 본문을 오류 메시지에 포함해 원인을 확인할 수 있게 함

세 문제는 모두 잘못된 결과가 정상처럼 화면에 표시될 수 있다는 공통점이 있었습니다. 의료 데이터에서는 오류를 숨긴 채 결과를 제공하는 것이 더 위험하다고 판단해, 요청과 실제 처리 내용이 다르면 작업을 중단하고 원인을 표시하도록 워커 코드를 수정했습니다.

04추론 환경 변경

초기에는 클라우드 GPU를 사용했지만 비용과 콜드스타트(첫 요청이 느린 문제) 때문에 팀이 로컬 워크스테이션 추론 방식으로 전환했습니다. 워커가 서버에서 작업을 가져가도록 구성해 외부에서 워크스테이션에 직접 접속하지 않아도 되게 했습니다.

05회고

이 프로젝트에서는 새로운 기능을 만드는 것보다 이미 생성된 결과가 올바른지 검증하는 일을 주로 맡았습니다. 이후 데이터를 화면에 표시할 때는 계산에 사용된 코드와 입력이 무엇인지, 결과가 잘못됐을 때 시스템과 사용자가 이를 알아챌 수 있는지까지 확인해야 한다는 기준이 생겼습니다.
